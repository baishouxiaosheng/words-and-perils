# Words and Perils 开发操作规范

目标：减少重复恢复、错基线修改、重复测试和交接报错，以最快可验证的小步骤推进。本文规定操作方式，不代表下述脚本、能力或测试已经实现、启用或通过。

所有者指定的唯一共同总计划是当前工作事实入口，属于私有内容。无法访问时，由协调者提供本任务的最小范围；不要创建第二份总计划，也不要把私有计划 URL 或 metadata 写入公开仓库。公开证据入口为 `candidates/`、`coordination/local-work/results/` 和任务明确指定的记录目录。

## 1. 先绑定任务，再开工

记录任务 ID、唯一 owner、不可变 base commit、输入路径及必要 hash、允许改动路径、验收目标、执行环境和下一步。先查已有 claim、checkpoint 和结果，避免重复任务。同一文件不得有两个并行写者；独立任务可以并行，合并与 main 发布串行。可信队列任务继续使用其现有锁、claim、去重和 STOP 规则，不以本文替代。

## 2. 源码和引擎分开安排

源码阅读、编辑、补丁生成及离线静态检查优先使用可用的已授权云环境。Godot 解析、headless、Main、GUI、视频或 FPS 必须使用当前已授权且 guard 条件完整的原生执行器。电脑关机或断开时，不派发依赖它的新任务；可继续独立、已授权的源码工作，并保留运行待办。明确失败的云续接不盲目重建；状态 UNKNOWN 先核已有线程和产物，同因两次失败后停止该续接路线并报告。缺少粘贴入口时可使用当前受支持、已允许的逐键输入；工具缺失不等于整台电脑不可用。审批拒绝不能靠换执行器或路线绕过。

## 3. 只恢复精确基线，保持输入字节可复现

根目录文件、已发布版本和候选 overlay 可能不是同一源码，禁止凭相同文件名互换。按本任务 manifest 恢复至新可弃目录，核实输入 bytes、SHA-256、project.godot 和所需依赖，再应用候选。新写的跨平台源码、补丁及文档默认 UTF-8/LF；先校验旧输入原始字节，不为匹配 hash 擅自转换旧基线。换行差异应作为明确候选变更处理，不全仓 renormalize。现有 `tools/restore_v30.py --project <目录> --check` 是只读源码/映射/闭包检查，不读二进制资源；`--sources-only` 会恢复并核实源码，二者都不等于完整资源或运行验证。

## 4. 候选、证据、采用分开

小改动只写任务允许的文件，把生产 overlay、test-only overlay 和 patch 清楚区分。候选放独立子目录，记录基线、应用方式、缺失依赖及未跑项；日志和验收记录绑定这次实际运行的源码，不复制旧通过回执。正式采用单独核对已有授权范围与对应验收记录；已有授权覆盖时不重复询问。不得把候选直接覆盖正式源码或真实存档来制造通过；根 README 保持空白。

## 5. 每项验证留一个可重复入口

复用已存在、已核源码的入口；不存在则先实现并验证，不在交接里假设它已可用。记录 cwd、工具绝对路径/版本、完整参数、测试脚本、fixture、种子、隔离数据目录、输出位置和源码绑定。先做补丁可应用性、静态断言和相关依赖检查，再安排引擎。引擎的 `--check-only --script` 只算解析检查；headless 不代替真实 GUI、鼠标、IME、DPI、视觉或 FPS。每次引擎启动，包括版本/帮助/解析检查，都服从适用 guard。

## 6. 按风险测试，不重复无关全量工作

改动前列出受影响行为和最小回归集。源码/文档改动先静态；存档改动覆盖读写失败、类型/边界、身份及隔离；交互改动覆盖打断、反向恢复、重复输入、取消和事件泄漏；跨模块或真实 Main 再追加集成/GUI。用本任务适用的风险决定升级测试。复用同一不可变基线已有的未变项证据，不反复给无关全仓、资源或 ZIP 做全量 hash；但新下载/恢复的输入、变更文件、实际运行源码及发布产物必须按任务要求核实。可信队列和恢复器已有必需全量校验仍照做，不能为速度跳过。分别报告 passed / failed / blocked / not-run 和实际计数。

## 7. 引擎资源与清理底线不变

使用已批准、SHA 核实的 guard。真实物理限额保持 `min(真实物理容量, 8 GiB)`，物理预留至少 512 MiB；Small 额外预算为 1024 MiB / 120 秒，Full 额外预算为 1741 MiB / 180 秒，并保留更严格规则。Job commit 限额不叫物理 RSS。要求的物理内存或 cgroup 指标不可读、准入不足、来源/claim 不明或 STOP 生效时，不启动引擎。使用任务所需的隔离精确源码副本与已核实隔离的 user://；仅写入性或污染风险要求新可弃副本，已验证隔离且未变输入可复用，不为每次启动重复复制。原任务的双 API、新副本及其他更严格要求仍照做。同机引擎、大规模 hash/复制和渲染串行，避免抢占物理余量；只清理身份确认的 owned 进程和任务可弃路径，不杀未知进程。保存 guard/宿主/引擎退出、输出、reader 完成及 Job/owned 句柄退出证据，失败产物保留。

## 8. 先分清失败，再重试

失败分为代码、环境、服务和审批：代码修复后只重跑受影响项；环境缺条件先修复获准的条件或保留 blocked；服务失败核实状态后使用支持的有界重试；审批拒绝先暂停该动作，报告准确目标与阻塞；若只是缺少原授权证据，补足直接授权后仅重试原工具调用一次，再拒绝即停止并报告，不能换路线绕过。用户取消则立即停止相关工作。阻断只暂停依赖该条件的部分，立即选择另一项已授权、依赖齐备且 owner 无冲突的游戏工作推进，同时独立排障，记录实际产出与恢复条件。同因两败停止原样路线，不等于停止整个项目；不得以反复查状态或补文档代替功能进展，也不提前抢做依赖未满足的后期任务。UNKNOWN 不能算失败后安全重开，也不能算完成。保留原始 stdout、stderr、退出码和 `SCRIPT ERROR` / `ERROR` / 警告。exit 0 只说明进程正常退出，不能吞掉诊断；预期错误须由测试明确标记并核对，其余错误未解决时不得宣称干净通过。功能通过与诊断干净分别描述。

## 9. 发布只做快进，并回读验证

仅上传获准的源码、资源、候选和去敏证据，不上传密钥、个人信息或真实玩家档。写前读当前 main；使用精确当前 head 的单亲 commit 和 expected-head CAS、快进更新，不 force，不重写历史。main 变化先核任务/输入/STOP/去重并保留其他改动，再构建新提交。关键源码/日志/清单先发布，结果再引用对应产物 commit/hash，避免包含自身 commit/hash 的循环回执。回读实际远端路径与内容后才报告上传成功。空队列、状态未变不产生空提交。普通源码任务不得自行修改锁定协议、trustedqueue 授权范围、安全设置或自动化入口。

## 10. 同步事实，交接只留必要信息

源码改变时同步受影响用法、manifest 和本任务结果；当前状态更新唯一共同总计划，不在多份文档复制。文档说明当前已确认状态，不记录 AI 修订流水；旧 A 被 B 替代后，A 退出当前说明，保留为带日期、证据和替代关系的独立历史记录。未确认的实现偏差不写成业务规则，不从旧规则推断当前能力。安全停点交接任务 ID、owner、commit/input 绑定、已完成/未跑项、产物位置、阻塞和精确下一步；由协调者直接续接受支持任务，不要求所有者手动搬运对话。checkpoint 不证明原生 compaction 可用，也不包含私人元数据或内部推理。

## 一手技术依据

- Git 的 `text` 与 `eol` 属性会影响 index/工作树换行，因此固定输入 hash 要绑定原始字节，不能把自动换行转换当成相同文件：[gitattributes](https://git-scm.com/docs/gitattributes.html)。本文没有安装 `.gitattributes` 或执行全仓重新规范化。
- Godot 4.6 文档将 `--check-only` 定义为与 `--script` 配合的解析检查，未知参数可能被忽略。运行记录应核实际二进制及参数支持，不能把静态、解析或 headless 当成 GUI 验收：[命令行文档](https://docs.godotengine.org/en/4.6/tutorials/editor/command_line_tutorial.html)。
