# 城市公开请求容量：显式、有上限的应用策略

## 这次解决什么

此前删除重复说明只省下425字节。64 KiB下，原城市短意图能发送，但240字节的普通中文意图和已有回合记忆会被拒绝。本次不删事实、不缩短指令、不压缩玩家文字、不改模型，而是让玩家明确选择一个有限的应用预算。

这只是本应用允许发送的公开JSON字节数，**不是服务商已验证的上下文窗口，也不是token数**。没有使用真实凭据或调用真实服务。

## 使用方法和兼容规则

在“连接与高级 → AI接口设置 → 公开内容上限”选择：

- **64 KiB（兼容）**：65,536字节，默认值；旧调用省略新字段时仍保持此值
- **96 KiB（城市推荐）**：98,304字节；需要明确选择、勾选现有发送/计费说明并点击“应用”
- **自定义字节**：1至131,072之间的精确整数；无效或超限输入直接报错，不自动夹到最近值，不自动提高较低限制

选择或应用本身不发送请求。改动未应用时禁用请求；正在请求时不能改设置。应用较大上限后仍要由原有明确按钮或已明确启用的结束回合请求触发发送；不会为此前的失败自动重试。清除连接后恢复离线和64 KiB显示。设置只保存在本次运行内存，不写入存档。

界面报告“公开内容实际字节 / 已选上限”，发送状态另列封装后的HTTP体积。两者不同：Chat Completions会把公开JSON放在字符串中，增加转义和系统说明；现有独立4 MiB HTTP体积检查保持不变。上限提高本身不填充数据，但允许实际较大的输入，因此可能增加输入费用。服务商容量、token计算和费用仍需玩家向提供商核实。

## 为什么推荐96 KiB，并封顶128 KiB

实际六回合城市公开请求为68,503字节，九回合为69,295字节。96 KiB在后者之上留下29,009字节余量，可容纳这些实测城市流程和普通中文意图；旧公开记忆本身仍按原有最多6条、4,096记录字节的政策返回完整记录和明确省略标记。本次没有修改该记忆政策。

128 KiB是刻意有限的自定义应用上界，防止无限扩大输入。它不承诺任意长度文字、任意公开扩展或未来内容都能通过。超过玩家选择的限制时严格拒绝发送，显示实际字节和限制；不裁剪必需内容、不猜测缺少的事实、不改变世界或待处理回合。

## 协议与身份不变

- 请求投影函数本体和Codec不变：完整必需公开对象、合同、指令、玩家文字、已选关注和文本优先级不变
- 全量context_hash、transport authority hash、完整公开请求摘要不变；预算仅属于本地连接设置和诊断，不进入请求JSON或存档
- 每个发送尝试固定自己的预算；在途修改被拒绝。发送前UI信号中途改变连接/同意状态也会拒绝发送
- 每次请求有独立操作身份，取消后嵌套开始的新请求不会被旧调用清除
- 新设置只用于后续明确发送尝试。读取同一个旧待处理存档不会从存档获得更大预算
- 每次超限都发生在transport.send之前；没有自动重试、服务替换、模型替换或额外回合
- 现有隐藏信息过滤、精确事实引用、公开扩展、权威结算、RNG、回执与存档协议不变

最终结果记录在`artifacts/runtime_ai_capacity_20261004/`。测试全部使用本地注入mock或明确署名样例，无真实API。焦点测试覆盖64/96/自定义边界、中文/emoji/转义UTF-8、无效配置、低限额、同意/应用、重新绑定、发送前重入、在途冻结、完整事实/记忆、模型与输出限制、保存恢复身份和只读叙事。

原生城市流程通过实际main按钮、署名离线评估经注入mock返回、正常程序掷骰/提交来验证连续行动；长自由中文只测量/发送到mock后取消，不用样例假装理解任意文本。另有独立进程读档继续测试。详细通过数和截图由最终验收汇总列出。

运行：在能读取真实cgroup的原生dot云端终端执行`bash tests/runtime_ai_capacity/run_regressions.sh`。始终单引擎串行，8 GiB实际cgroup减512 MiB预留保护；不能改用看不到真实cgroup的执行环境绕过保护。
