# Lazy typed attention regression and selection benchmark

These are test-only consumers of the exact-production engine copies generated by
`generated/{old_engine,new_engine}.gd`. The copies' `facts_calls` counters wrap
only the actual full `ModelView.facts` expression inside `attention()`. They do
not infer calls from a typed/legacy label. The production-copy generation and
reversibility evidence are maintained separately by the validation owner.

## Entry points

- `res://tests/lazy_typed_attention/test_parity.gd`: headless-compatible focused
  regression using one real seed 726381, radius 12, coastal source admitted
  through the NPC Adapter with vegetation enabled
- `res://tests/lazy_typed_attention/test_main_benchmark.gd`: native full-Main
  selection benchmark using one real admitted source and one Main instance
- `support.gd`: shared test harness; neither runtime behavior nor production
  files are edited by the tests

Launch only through the native memory/resource guard and serialized engine
slot. The accepted owner-run results below used the unchanged 512 MiB reserve
and 240-second per-process cap.

Reports are written to `res://artifacts/lazy_typed_attention/` as
`parity_report.json` and `main_benchmark_report.json`.

## Regression boundaries

The same exact engine save (including RNG, action counter, receipts, and pending
request identity) is loaded into old and new copies built with the real admitted
state, calculator, resolvers, and policy. Every attention call compares the
canonical output bytes and verifies read-only save/RNG/request/pending target
identity. Typed NPC, item, vegetation, and representative static kinds are
covered, together with ordinary actor, tile, and empty legacy attention.

Negative references cover every mandatory field, extra fields, unknown exact
catalog version, catalog identity, stable ID, world, scene, hex, and stale
revision. Genuine assessed movement and dropping create stale carried-location
and custody references without directly editing authority. A real pending NPC
intent is queried with all focus kinds, JSON-engine-loaded, then queried again;
its original target and complete request remain exact.

The scene-guard test is explicitly fault injection into private engine copies:
it temporarily changes only the acting player's scene, requires `FOCUS_SCENE`
and zero facts calls for an otherwise resolved typed static reference, checks
no further mutation, and restores the exact original scene immediately. This
is negative guard evidence, not an admitted world or a supported travel claim.
The tests do not construct fake scenes or publish manufactured gameplay state.

## Benchmark boundaries and pairing

Main is instantiated with `startup_legacy = true` and receives the same real
NPC Adapter via its normal mode switch. The benchmark finds a genuine visible
foreground NPC and plant with `board.pick_focus`, retains each complete ordered
candidate list, and feeds it unchanged to `Main.on_focus_candidates`. It never
promotes a hidden hit or substitutes a synthetic picker/proxy reference.

The timed synchronous operation includes focus validation/projection, Main's
selection, focus label/details preparation, board highlight update, and movement
preview UI. It excludes startup, source generation/admission, camera setup, raw
picking, render-frame latency, and the test's before/after identity assertions.
Thus the result is complete Main selection-handler CPU latency after a real raw
pick, not click-to-photon time or picker-only timing.

Each kind has one untimed warmup per variant and four measured pairs, ordered
old/new, new/old, old/new, new/old. Each sample starts from cleared selection and
identical authoritative bytes; the same camera and raw candidates are retained
within that kind. Reports retain all raw samples, operation-input hashes,
authority/request/RNG/pending witnesses, actual facts-call counts, exact UI
parity checks, and per-variant median/min/max/mean. No noisy latency threshold
is used as a correctness gate. Typed old calls must be exactly one and typed new
calls zero; legacy accepted calls must remain one in both copies.

A final real pending NPC intent verifies that a subsequent Main plant click
changes only the next selected target. This benchmark does not claim runtime AI
controller or network transport parity; those are owned by their dedicated QA.

## Resource scope

Each entry point admits one world; the two engine copies share the admitted
calculator/resolver setup and do not create additional terrain renderers. The
Main benchmark creates one generated board. Raw plant search is bounded to 24
real manifest plants and three points per plant. The pair count is fixed and
small. There are no network requests, user saves, new full-game copies, runtime
script rewrites, or indefinite monitoring loops.

## Accepted native results (2026-10-05)

- Focused parity: 1,036 checks, 98 cases, clean exit 0 in 131.2 seconds
- Exact case split: 20 typed calls (old 1 / new 0 full-facts calls), 10 legacy
  calls (1 / 1), 68 rejected references (0 / 0)
- Actual Main benchmark: 98 checks, 16 measured operations, clean exit 0 in
  41.3 seconds, equal warmups and two AB plus two BA pairs per subject
- NPC synchronous selection median: 230.4615 ms before, 9.113 ms after
- Vegetation synchronous selection median: 303.259 ms before, 90.8485 ms after
- Every measured UI and authority witness matched; no renderer or source
  geometry changed. Actual picker runs preceded the measured handler
- Benchmark peak RSS: 954,056 KiB; peak shared cgroup: 7,773,384,704 bytes,
  below the unchanged 8,053,063,680-byte stop. These include test engine copies

The two diagnostic extra legacy scripts are not acceptance evidence: one lacks
its historical baseline fixture; the creative coast fixture cannot construct
its world in the compact stage. Their failed attempts are preserved separately.
The broader known-good legacy save/controller gate belongs to combined-release
validation, rather than this standalone focus suite.

Timing provenance retains exact post-run Main, controller, engine and test
copies. The owning gameplay lane explicitly held Main/controller during the
run; there was no pre-run cryptographic Main snapshot. This limit is explicit
in TIMED_SOURCE_PROVENANCE.json. Engine old/new instrumentation is separately
reversible to exact pinned before/after bytes. These software-renderer results
establish the synchronous application CPU saving only, not click-to-photon time,
steady FPS, or performance certification for a target GPU.
