# 村庄冒险：可选 AI 连接

## 玩家流程

1. 从同一个“村庄冒险”入口建立或继续进度；旧版探索、行囊和无村民村落仍从原继续入口恢复。
2. 默认离线。行动示例只填入预设文字，结束回合后需明确应用预设裁定。
3. 自由文字提交时冻结选中的对象和公开事实。连接与高级中的 AI 接口设置接受用户自己的接口、模型和内存凭据；勾选同意可能计费并应用后，可手动请求评估。应用设置不会发请求。自动评估和自动叙述均为独立选择。
4. 收到有效评估后，游戏规则负责检定、费用与一次提交。自由模型回复不能直接编辑世界、创造话题答案或越过范围检查。
5. 待评估时不能切换世界。取消和超时不会提交结果；重试使用新的传输身份。完成后的可选叙述可以随时被切换视图取消，迟到文字不会流入另一个冒险。
6. 保存仍使用原来的核心存档。最近64段可选叙述另存为同路径加 `.narration.json`；它只用于显示，不进入后续模型事实、费用、骰子或历史裁定。加载失败的核心进度保持当前会话；文字文件损坏只警告并忽略。

## 边界

- 只为当前 `generated_v3_village_npc/v1` 连接完整且已限界的公开请求，不重新使用旧海岸的邻域裁剪。
- 村庄请求固定上限65,536字节，意图仍限4096字节。连接预算较小时还须满足较小预算；选择96 KiB不能解除该存档的64 KiB限制。超限明确拒绝，事实和目标不截断。
- 评估回复限64 KiB，叙述限8 KiB。普通换行、制表和回车保留；其他C0控制文字拒绝，避免形成外部消费者无法读取的JSON。
- 提交时的目标、世界、回合、请求令牌和精确回执身份负责防止重复、迟到或跨进度应用。手工导入叙述与接口叙述共用同一幂等显示记录。
- 未改变模型列表、世界身份、规则、源资料、存档协议、既有海岸容量设置或原来的继续入口。
- 当前只验证本地Mock传输。没有使用真实凭据、真实服务调用或计费记录；Mock界面明确显示离线测试。

## 开发接口

`bounded_profile_engine.gd` 是显式选用的传输边界，保持实际引擎公开请求的规范化字节不变。`village_session.gd` 是视图会话外观，提供精确回执绑定的可选叙述记录。两者都不参与Source或规则身份。

测试覆盖自然文字问路、已学知识和远处植物支持格、同步回复、超时/重试、忙闲事件中的重入替换、最终通知中的替换、锁定后重复请求、取消、跨世界迟到文字、主界面保存/恢复和单独进程叙述恢复。采用量与最终结果以发布验收清单为准。
