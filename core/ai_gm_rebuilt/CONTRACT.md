# AI-GM rebuild v1: isolated execution contract

This is new source reconstructed from confirmed requirements on 2026-10-02. It is not recovered lost source and does not inherit old test PASS counts. It does not replace `core/game_state.gd`, the schema-1 D20 relay, `main.gd`, or any UI/terrain/geography code. Existing v9 compatibility remains untouched.

## Boundaries

The engine has a separate `ai_gm_rebuilt/v1` schema and no runtime API provider. Every deliberate player action starts with an external assessment, including apparently harmless actions. Empty text and attention clicks never start an action. Player text is retained verbatim and is authoritative over attention context. Attention uses the existing exact `focus_contract.gd`; no clicked object silently becomes an action target.

Public model context is an explicit field allowlist projection of a versioned frozen snapshot. NPC secrets are absent unless individual secret pointers were explicitly allowlisted. RNG seed/state, receipts, attempt ledger, staged commits and pending internals are never public model fields. Model replies are typed data, never executable code, arbitrary paths, or scripts. Narration cannot patch facts.

## Lifecycle

`awaiting_assessment -> ready_roll -> rolled -> staged -> committed`

The calculator is a trusted injected plugin. The default is `NOT_CONFIGURED`, so this engine makes no invented production ruling. Assessment components and exact public fact references must validate before the calculator runs. A trusted pre-registered consequence resolver freezes exhaustive, non-overlapping candidate branches, resource costs and explicitly configured actor hooks before any roll. Every branch is validated before publication. The fixed calculator decides direct success, direct failure or a random threshold; the production balancing formula is deliberately unresolved.

Dice are generated by Godot's real RNG, once per action. The numeric domain/threshold is supplied by the calculator, not permanently fixed to D20 or D100. Internal signed 64-bit seed/state are decimal strings in saves. Repeating the same rolled/staged action returns the same result; reloading an earlier stage preserves the RNG sequence. This is deterministic replay within a save lineage, not an anti-tampering guarantee against edited saves or deliberately forked worlds.

Stage applies only the selected frozen branch to a copy. Commit verifies its frozen hash, validates the copy, advances both `state_version` and `turn` exactly once, and publishes facts plus an idempotent receipt atomically. Repeated commit with the same token is a no-op; conflicting tokens are refused. Attempt fingerprints come from the registered resolver and real relevant conditions, excluding prose, versions and turn counters. Mere paraphrasing cannot unlock a fresh attempt. This version requires changed material facts and does not enable a new-turn exception; an explicit new-turn retry policy remains a future rule decision.

## World integrity

Actors, items, cells, scenes, story anchors and status entries use stable IDs. Typed patches are limited to documented operations; unknown types, arbitrary field writes, non-finite numbers, stale versions, invalid references and stable-ID changes fail without facts changing. Scene layers are a framework only; no detailed layered adventure is implied.

Pathfinding and reachable ranges use the same traversal predicate. Flight bypasses `ground_blocked`, never `all_blocked` or `air_blocked`. A fallen tree may set the supporting cell's ground block; no new fallen-tree mesh or entity is required. Code runs only preconfigured patrol/status hooks, sorted by stable actor ID and stable status ID. Rich patrol/drunk/poison systems are extensions, not mandatory game rules.

## Test-only demonstration

`tests/experimental/ai_gm_rebuilt/test_rule_a.gd` is labelled `ai_gm_test_rule_a/v1` and must be explicitly injected. Its basis-point formula is clamp(5000 + 1000 * (A - D + P + clamp(R - N, -2, 2)), 500, 9500), with A/D 0..4, P -2..2 and R/N 0..2 derived from frozen wine placement/quantity and living soldiers in the same scene. It is a test fixture, not a final balance decision. Fixture assessments demonstrate program integrity and cannot certify real model interpretation, judgment or narrative quality. Runtime model preferences 6.1-sol low / 6.0-luna remain future configuration and are not changed here.

Run the standalone Godot integration script documented with the test report. No UI integration or live API is claimed.

## Final narration and save trust

`authoritative_result` supplies immutable recorded component results, actual public dice and projected public effects. `narration_request` can describe a staged result or an already committed historical result. Its optional text-only reply is validated by schema, action ID, version and context hash; `validate_narration_reply` does not mutate facts/receipt/RNG/plan/token and is never a commit prerequisite. Structural validity cannot prove narration is semantically true. A future UI must preserve the authoritative result beside any display narrative.

Loaded disclosure policy must equal the trusted initialized runtime policy exactly. A save is not permission to disclose more NPC secrets or flags. JSON validation is depth-bounded to 64 levels and safely rejects cyclic direct/plugin inputs. Committed receipts retain actual roll values for historical audit without exposing RNG seed/state.

`cancel_intent` only removes awaiting-assessment or ready-roll intent metadata while its frozen facts and RNG remain unchanged. It preserves committed attempt/receipt history and never reuses an action ID. Rolled, direct-resolved, staged and committed actions cannot be cancelled to reroll. Corrected intent must start a new request and revalidate fresh frozen facts.
