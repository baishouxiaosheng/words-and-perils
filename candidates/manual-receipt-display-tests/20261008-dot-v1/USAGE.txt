Finite flow:
1. Boot the actual public-v30 Main, install the existing no-network mock before any provider configuration, and keep all automatic model calls off.
2. Generate the existing seed726381/radius4/coastal_range source, admit the real legacy enemy adapter, then use the actual advanced-menu ACTOR_ENTRY_NEW route into independent actor_actions_v2.
3. Follow at most32 real source navigation edges to the contact anchor. Every move/rest is separately evaluated and committed by the real Engine through Main; movement is revalidated after rest.
4. Evaluate and commit one real enemy observe action, returning to the player slot. Keep the actual player and enemy receipts from that chain.
5. Run pending_import for the earlier player receipt; its real new pending is then canceled through Main without time/RNG/receipt mutation.
6. Run pending_import for the latest enemy receipt; cancel its real new pending the same way.
7. Commit two further real ordinary observe actions, player then enemy, to obtain an un-narrated latest enemy receipt; run idle_latest_import.

The three helper calls include unknown/duplicate import checks. The source/Engine is never reset or substituted. There is only one contact route. Published helper comments recommend separate fresh fixtures; this integration instead supplies a genuinely un-narrated receipt for each first-import check and validates the same real source/profile at every call, avoiding three redundant approach journeys. No changed helper bytes or forged save/receipt are used.
